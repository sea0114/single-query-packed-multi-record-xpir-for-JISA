# Expanded mechanism comparison

## Taxonomy and mechanism matrix

A = weighted/packed multi-value retrieval; B = batch/bucket/SIMD; C = preprocessing/hint/short-record context. Categories overlap. A scalar digit within a polynomial coefficient is not a SIMD slot; neither is it a bucket. “Hintless” concerns client-downloaded database hints, not all server or evaluation-key state.

| Scheme | Multi-record mechanism | Underlying primitive | Batch placement / hashing | SIMD / rotations | Preprocessing / reusable state | Query / reply structure | Primary scaling bottleneck | Security model | This-paper relationship |
|---|---|---|---|---|---|---|---|---|---|
| XPIR [X] | Repetition; aggregation/recursion optimize its database representation | Lattice/RLWE-based homomorphic encryption | No PBC required by the flat path | NTT arithmetic is not a SIMD batch mechanism | Encoded/NTT database; public crypto configuration | Flat path: encrypted selector vector, linear database absorption, ciphertext reply blocks; broader recursive options | Scan/absorption, ciphertext communication, block layout and parameter choice | Computational index privacy under its HE assumptions; native sampler is not automatically the formal law | Closest backend; concurrent same-profile repetition is the measured comparator; optimized cross-profile timing is not claimed |
| Hsu et al. 2020 [H], A | Encrypted selected weights, homomorphic weighted sum, integer remainder recovery; arbitrary count subject to modulus | Group-based additively homomorphic public-key encryption | No batch placement needed for this construction | No RLWE SIMD requirement | Public-key setup; client chooses and retains recovery weights | Length-of-database encrypted vector and a weighted encrypted sum for the scalar-value model | Query length, growing weights, plaintext modulus / retrieval count | Privacy argument from the underlying IND-CPA encryption; not this manuscript's PLWE/sample reduction | Closest conceptual prior art; already supplies the generic mechanism and modulus limitation |
| SealPIR / PBC line [S], B | SealPIR compresses selection queries; separate PBC transformation serves a batch over buckets | RLWE/BFV through SEAL | PBC uses replicated placement and cuckoo assignment of requested items to buckets | Homomorphic expansion for compressed queries; do not equate this with integer radix or require every SIMD technique | Encoded DB, bucket replication for PBC, expansion/evaluation material | Compact query expanded at server; per-bucket queries/replies under PBC | Expansion, database work, bucket/replication overhead and batch-code failure | HE-based query privacy; PBC placement/failure and reusable material must be accounted for | Query compression and batch scheduling alternatives; no local empirical comparator |
| Vectorized BatchPIR [V], B | Vectorized batch processing plus ciphertext merging | RLWE/BFV | Bucketed / cuckoo-based batch layout | SIMD, rotations, merging are central | Encoded buckets and client evaluation/rotation keys | Encoded batch query; slot-wise bucket processing and merged response | Slot occupancy, rotations/merging, bucket count, bandwidth | Computational privacy under its RLWE/HE model, including evaluation-key/circular-security discussion; placement failure separate | Distinct placement/slot mechanism; architecture difference does not establish a winner |
| PIRANA [P], B | Constant-weight index encoding; payload-specific packing and multi-query PBC route | BFV/RLWE homomorphic encryption | Batch-code route with cuckoo placement | Slots and rotations; dependence on payload size/configuration | Encoded DB/buckets; reusable rotation/evaluation keys | Constant-weight encrypted selection; payload-specific reply organization across batch buckets | Code length/weight, homomorphic selection work, rotations, bucket overhead | HE-based query privacy with evaluation material; batch-placement and HE correctness obligations | Direct multi-query comparator in literature only; not an admitted runtime baseline |
| SimplePIR / DoublePIR [D], C | Base protocols retrieve records through LWE linear algebra; multiple queries may reuse a database-dependent hint | LWE (not the same RLWE family as this manuscript) | Not required for their base schemes | SIMD machine instructions are not homomorphic slot/radix packing | Client downloads DB-dependent hint; DoublePIR adds processing to reduce hint size; server DB preparation | LWE query and matrix-vector response; hint used for extraction; DoublePIR compresses hint via another layer | Database scan/memory bandwidth, hint communication/storage, amortization and updates | LWE-based client index privacy; correctness/noise and preprocessing model differ | Shows why online bytes/time alone omit material costs; not weighted-packing prior art |
| Respire [R], B/C | Subring embeddings, ring switching and response packing; PBC batching | RLWE-based HE / GSW-style encodings | PBC/cuckoo route for batch version | Polynomial/subring packing and automorphism/ring-switching operations; not scalar base-B digits | Client supplies reusable query-key material; server silently preprocesses DB; this is not SimplePIR's downloaded DB hint | Compressed query, query expansion/evaluation, packed response | Ring/record sizes, expansion, switching, packing and batch organization | Computational privacy in its stated reusable-key model; HE and PBC correctness; no transfer of its parameters to this construction | Direct precedent for short records, small batches and response packing |
| SPIRIT [T], B/C | Stateful LWE-to-RLWE conversion, shared expansion and compressed batch responses | LWE/RLWE (BFV), intermediate module representation and RGSW material | PBC/cuckoo schedule | Homomorphic response packing with shared intermediates; distinct from integer radix | Server bucket-specific auxiliary matrices/preprocessing and per-query shared expansion state; client sends key material, no offline downloaded DB hint | One batch query; shared key expansion then bucket-local conversion and compressed responses | Bucket scans, conversion/expansion, packing and server state | Semi-honest batch index privacy (Theorem 3.1); correctness includes conversion/LWE and PBC failures (Theorem 3.2) | Direct precedent for hintless batch PIR; hintless does not imply stateless or no preprocessing |
| Radix-XPIR, A | Fixed public powers of B encode multiple bounded integers in each coefficient; ordinary radix extraction | Direct symmetric-key RLWE/PLWE interface; specified rounded-continuous-normal family | No extra batch-placement/hashing step | No SIMD rotation/merging needed for record separation; polynomial NTT arithmetic retained | Encoded DB/NTT representation and fixed public layout; fresh client secret per query, no downloaded DB hint | N encrypted constants (including zeros), L linear response ciphertexts | Exact plaintext capacity, all-database aggregate noise, N*L absorption, native integer API and secure parameters | Single-challenge ordered-index privacy; Theorem 2 uses N+1 uPLWE samples and unit-probability loss; Theorem 1 conditional on no-wrap; no native security certificate | Restricted instantiation/formal-to-native study; finite executed native profiles are reported; no native security certificate |
